# AGENTS.md — nvim-config

Personal Neovim config (lazy.nvim based). Read this before changing anything.

## Model rules (non-negotiable)

- **Never commit, stage, or otherwise mutate git state on your own.** The user
  commits. Leave changes uncommitted and say so.
- **Never make a choice on your own.** If a decision is needed (file format,
  naming, behavior, scope, trade-offs), ask the user with a concrete question
  and wait for the answer. Do not pick a default silently.

## Layout

- `init.lua` — bootstraps lazy.nvim, loads `lua/vim-options.lua`, then `require("lazy").setup("plugins")`.
- `lua/vim-options.lua` — core vim options (leader, tabs, clipboard, ...).
- `lua/plugins/*.lua` — one lazy.nvim plugin spec per file, loaded via `require("lazy").setup("plugins")`.
- `lua/config/schema.lua` — declarative list of every user-changeable setting (100 entries), grouped by plugin via `group`. Entry fields: `group`, `key` (dot-path), `label`, `type` (`string`/`number`/`boolean`/`enum`/`display`), `default`, `desc`, plus `options` (enum) / `min`,`max` (number). `display` = read-only, function/table-based settings that can't be menu-edited.
- `lua/config/settings.lua` — runtime module. Merges schema defaults with `lua/config/local.json` overrides into `values`; exposes `entries` (for the menu) and `get("dot.path")`. Plugin files must read settings from here: `require("config.settings").values.<path>`.
- `lua/config/local.json` — per-user overrides, **generated by the settings menu, gitignored, never commit it**.
- `lua/config/menu.lua` — the settings menu UI (required from `init.lua`). Open with `:ConfigSettings` or `<leader>cs` (only bound if free). Two-pane float: left = plugin groups, right = that group's settings. Edits auto-save to `local.json`; `live_apply` keys apply immediately, everything else triggers an automatic Neovim restart on exit.
- `lazy-lock.json` — pinned plugin versions.
- `README.md` / `CHEATSHEET.md` — user docs; keep them in sync with keymap/setting changes.

## Settings flow

`schema.lua` (defaults + metadata) → `settings.lua` (merge with `local.json`) →
`lua/plugins/*.lua` (consume values) → Telescope settings menu (writes `local.json`).

Rule: a plugin file never hardcodes a value that exists in the schema.

## Conventions

- Keymaps use `<leader>` (leader = space) unless the key is a control key.
- New user-changeable setting → add a schema entry first, then wire the plugin file to it.
- `command_variants` flags (`--continue`, `--resume`, `--verbose`) are specific to the configured AI harness command; adjust when changing `harness.command`.
- Test modules without loading the full config: `nvim --headless --clean -c "set rtp+=." -c "lua ..." -c "qa!"` from the repo root.
- Work happens on feature branches; `main` stays the stable, pushed state.
